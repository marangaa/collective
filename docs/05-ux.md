# 05 — UX & interface

## Personas

1. **Community member** — low-end Android, 3G or worse, Swahili-first, may be standing in
   front of the actual building. Wants: "was our clinic supposed to be done? can I say what
   I see?"
2. **Ward investigator / CSO / journalist** — desktop, wants the full chain, exportable.
3. **Reviewer** (us + partners) — the claim-approval console.
4. **Judge / first-time visitor** — 90 seconds to understand the thesis.

## The core screen: the Case File

The organizing idea: **the story of one place, told at every step in time — record vs
reality.** Desktop: timeline left (scrolls), map right (sticky, follows the story). Mobile:
stacked, map collapsible. Every element obeys one rule — *tap anything, see its source.*

**Sections, top to bottom:**

1. **Header** — project name, ward/county, sector. Verdict strip: five aspect chips
   (budget, award, payments, delivery, current state) in fixed semantic colors:
   green = corroborated, red = contradicted, grey = unverifiable, amber = partial.
   These colors are never used decoratively anywhere else. Underneath: *"Record last
   verified 12 days ago"* — freshness as a first-class citizen.
2. **The tension summary** — two sentences, system-generated from verdicts:
   *"The county paid KSh 165.1M for Phase II. Three audits and a 2025 re-tender indicate it
   was never completed."* Record vs reality, in plain language.
3. **Timeline** — vertical, grouped by OCDS stage (Budgeted → Tendered → Awarded → Paid →
   Claimed → Audited → Observed). Each node: date, one-line assertion, source-type marker
   (official / independent / community). Expand a node → its **evidence card**.
4. **Map** — the four facilities as pins colored by current verdict; ward polygon; field
   reports as clustered dots. Scrolling the timeline pans the map to the facility in focus
   (story-map pattern). Offline/low-bandwidth: map collapses to a list — it is an
   enhancement, never a dependency.
5. **Evidence card (drawer)** — the claim, then: verbatim excerpt, document title, page,
   publisher, retrieval date, SHA-256 (short), link to the original. This card is the
   product's soul: *don't trust us, check.*
6. **Contradictions** — paired claims rendered side by side ("KSh 165,099,105 paid" vs
   "site abandoned since March 2023"), with the documents behind each. The engine surfaces;
   the reader concludes.
7. **What's missing** — gap cards: *"No completion certificate in the public record."*
   Each gap resolves into a **next-step card**: the institution, why them, and a pre-filled
   **Access to Information Act request** (view / copy / download). This is the brief's
   "clear next steps" made literal.
8. **Community reports** — chronological, corroboration state visible ("3 independent
   reports in the last month"), photos, and the CTA: **"Were you there? Add what you saw."**
9. **Export** — the entire case file as a portable PDF/JSON bundle with hashes. Built for
   the investigator who walks into a county assembly committee room.

## Field-report flow (`/report`, mobile-first)

1. **Which place?** — nearby projects sorted by GPS distance (or pick from list/search).
2. **What did you see?** — four big buttons: Operational / Partially built / Stalled or
   abandoned / Never started. No free-text required.
3. **Photo** (optional) — camera capture; compressed and **EXIF-stripped on device**
   (photos routinely carry GPS metadata — we remove it before it ever leaves the phone).
4. **Note** (optional) — short text.
5. **Submit** — instantly queued: *"Saved. Will send when you're back online."* A sync chip
   shows pending/sent. Anonymous session is created silently on first use — no signup,
   no name, no phone number.

## Review console (`/console`, reviewer role)

Extraction queue: candidate claim ↔ source page side-by-side, approve/edit/reject with
keyboard speed. Reconciliation re-run trigger. Extraction-run stats (tokens, cost, pass
rates) — the trust dashboard for our own AI.

## Landing (`/`)

The hook in one screen: *"The county said it was built. Was it?"* → live case stats → the
case file. Plus "how verification works" in three diagrams (sources → evidence chain →
action). Judges land here; make the thesis undeniable in one scroll.

## Offline & low-bandwidth contract

| Surface | Offline behavior |
| --- | --- |
| Case file read | Last-viewed case cached by the service worker; staleness banner honest about age |
| Map | Optional layer; list fallback always present |
| Report flow | Fully offline-capable; outbox + later sync |
| Photos | Compressed before upload; resumable-ish via small multipart parts |
| API | Batched tRPC, small payloads, edge cache |

Background Sync API where it exists (Chromium); on iOS Safari it doesn't — fallback is
sync on `online` event + app open + a visible manual retry. We say this in the UI, not in
a footnote.

## i18n & accessibility

EN/SW string shell from day one (all UI copy through one dictionary); plain-language claim
summaries; KSh number formatting; minimum 16px body, high-contrast verdict colors paired
with icons (never color-only), full keyboard nav on the timeline.
